# Documentation

Terraform module that provisions a self-managed **[k3s](https://k3s.io/)
Kubernetes cluster on [Hetzner Cloud](https://www.hetzner.com/cloud)**: one (or
more) master nodes and a configurable number of worker nodes, all joined over a
private Hetzner network.

Diagrams are fenced ` ```mermaid ` blocks, so they render natively on GitHub and
in VS Code and stay diffable in review — no image files are committed.

## Quick start

```hcl
module "hcloud_kubernetes_cluster" {
  source = "github.com/pawel150199/hcloud-k8s-cluster"

  master_nodes_number = 1
  worker_nodes_number = 2

  # The only key material you supply: your own public key.
  # Optional - pass `ssh_keys` instead to reuse a key already in your project.
  ssh_public_key = trimspace(file("~/.ssh/id_ed25519.pub"))
}
```

The key pair the masters use to reach the workers, and the k3s join token every
node shares, are **generated by the module** and injected through cloud-init —
you never pass them in. See
[Architecture §2.5](02-architecture.md#25-ssh-key-model).

Nodes harden sshd on first boot: you log in as **`cluster`**, `root` and
password logins are refused, and `ssh -L` forwarding is disabled
([§2.7](02-architecture.md#27-node-ssh-hardening)). Set `use_tailscale = true`
with a `tailscale_auth_key` to reach the nodes over a tailnet with Tailscale SSH
instead ([§2.8](02-architecture.md#28-tailscale)).

See the [usage example](04-usage-example.md) for the full configuration, and
[getting started](03-getting-started.md) for the provider and backend setup that
must accompany it.
