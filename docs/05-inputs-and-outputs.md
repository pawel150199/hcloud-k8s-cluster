# 5. Inputs & outputs

Full reference for the module's variables (`variables.tf`) and outputs
(`outputs.tf`).

## 5.1 Inputs

### Cluster sizing

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `master_nodes_number` | `number` | `1` | Number of master (k3s server) nodes. Must be `1`, `3`, `5` or `7`; above 1 the masters form an HA control plane on embedded etcd |
| `worker_nodes_number` | `number` | `2` | Number of worker (k3s agent) nodes |
| `control_plane_load_balancer_type` | `string` | `"lb11"` | Hetzner load balancer type for the API |
| `control_plane_load_balancer_public` | `bool` | `false` | Give the API load balancer a public listener. Off by default, because Hetzner firewalls do not apply to load balancers and a public listener would bypass `kube_api_source_ips` |

### Node configuration

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `node_image` | `string` | `"ubuntu-26.04"` | OS image for every node (must be `apt`-based for cloud-init; the nodes run `package_upgrade` on first boot) |
| `master_node_type` | `string` | `"cx23"` | Hetzner server type of the masters. An HA control plane wants dedicated vCPUs (`ccx*`) |
| `worker_node_type` | `string` | `"cx23"` | Hetzner server type of the workers |
| `node_location` | `string` | `"fsn1"` | Hetzner location (`fsn1`, `nbg1`, `hel1`, …) |
| `node_enable_ipv4` | `bool` | `true` | Attach a public IPv4 to nodes |
| `node_enable_ipv6` | `bool` | `true` | Attach a public IPv6 to nodes |
| `k3s_version` | `string` | `"v1.36.4+k3s1"` | k3s release installed on every node |

### Kubernetes API certificate

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `extra_tls_sans` | `list(string)` | `[]` | Extra names/addresses added to the API server's `--tls-san`, on top of the master private IPs, the master public IP and the API load balancer. Add whatever host `kubectl` dials — a DNS name, a Tailscale `100.x` address or MagicDNS name — otherwise the TLS handshake fails on a name mismatch |

### Tailscale

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `use_tailscale` | `bool` | `false` | Install Tailscale during cloud-init on every node and run `tailscale up --ssh`. Nodes join the tailnet as `master-node-N` / `worker-node-N` |
| `tailscale_auth_key` | `string` (sensitive) | `"null"` | Pre-authorized auth key the nodes use to join. Required when `use_tailscale` is true, ignored otherwise — the default is the placeholder string `"null"`, not a real key |

Tailscale SSH bypasses sshd, so it is the one way in that survives the
`AllowUsers cluster` hardening with no `authorized_keys` entry at all; access is
governed by your tailnet ACLs instead. `41641/UDP` is open inbound on every node
whatever this flag is set to, so Tailscale can establish direct peer connections
rather than relaying through DERP. The auth key is rendered into `user_data` and
kept in the Terraform state — use an ephemeral, pre-approved key with a short
expiry. See [Architecture §2.8](02-architecture.md#28-tailscale).

### Networking

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `private_network_ip_range` | `string` | `"10.0.0.0/16"` | CIDR of the private `hcloud_network` |
| `private_network_subnet_ip_range` | `string` | `"10.0.1.0/24"` | CIDR of the subnet¹ |
| `private_network_zone` | `string` | `"eu-central"` | Network zone of the subnet¹ |
| `private_network_type` | `string` | `"cloud"` | Subnet type¹ |

### SSH keys

Only your own public key is an input, and even that is optional. The key pairs
used between the nodes are **generated by the module** — see
[Architecture §2.5](02-architecture.md#25-ssh-key-model).

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `ssh_public_key` | `string` | `null` | Public SSH key of your machine. Uploaded as `hcloud_ssh_key.admin` and installed on the `root` and `cluster` users of every node. Only the `cluster` entry is usable — sshd refuses `root`. Leave unset to rely on `ssh_keys` |
| `ssh_keys` | `list(string)` | `[]` | Names/IDs/fingerprints of SSH keys that already exist in the Hetzner project, installed on the nodes' `root` user and authorised for the `cluster` user, in addition to `ssh_public_key` |
| `ssh_key_algorithm` | `string` | `"ED25519"` | Algorithm of the generated node key pairs: `RSA`, `ECDSA` or `ED25519` |
| `ssh_key_rsa_bits` | `number` | `4096` | Key size, used only when `ssh_key_algorithm = "RSA"` |
| `ssh_key_ecdsa_curve` | `string` | `"P384"` | Curve, used only when `ssh_key_algorithm = "ECDSA"` |

`ssh_public_key` and `ssh_keys` are independent — use either, both, or neither:

| Configuration | Result |
| --- | --- |
| `ssh_public_key` only | The key is uploaded to Hetzner as `kubernetes-cluster-admin` and installed on `root` and `cluster` |
| `ssh_keys` only | No key is uploaded; the listed existing Hetzner keys are installed on `root` and authorised for `cluster` alongside the module-generated key |
| Both | The uploaded key and the existing ones are all installed on `root` and authorised for `cluster` |
| Neither | Nothing is authorised for `cluster`, and sshd accepts no other account — **the nodes are unreachable over SSH** unless `use_tailscale` is on |

You always log in as `cluster` (passwordless `sudo`): the nodes write an sshd
drop-in on first boot with `PermitRootLogin no`, `PasswordAuthentication no` and
`AllowUsers cluster`, and it also refuses `ssh -L` port forwarding and agent
forwarding. Full list in
[Architecture §2.7](02-architecture.md#27-node-ssh-hardening).

When it *is* set, `ssh_public_key` is validated: it must start with `ssh-rsa`,
`ssh-ed25519` or `ecdsa-sha2-nistp*`, i.e. be the contents of a `.pub` file —
not a path and not a private key.

> ¹ `main.tf` wires `private_network_type`, `private_network_zone` and
> `private_network_subnet_ip_range` into `hcloud_network_subnet`, and
> `private_network_ip_range` into `hcloud_network`.

## 5.2 Outputs

| Name | Type | Description |
| --- | --- | --- |
| `master_nodes_ips` | `list(string)` | Public IPv4 addresses of the master nodes |
| `worker_nodes_ips` | `list(string)` | Public IPv4 addresses of the worker nodes |
| `master_nodes_private_ips` | `list(string)` | Master private addresses in the cluster subnet |
| `worker_nodes_private_ips` | `list(string)` | Worker private addresses in the cluster subnet |
| `control_plane_endpoint` | `string` | Address the agents join through: the API load balancer when the control plane is HA, otherwise the first master |
| `control_plane_load_balancer_ipv4` | `string` | Public IPv4 of the API load balancer, or `null` when none is created |
| `cluster_token` | `string` (sensitive) | k3s join token shared by every node — needed to add a node by hand outside Terraform |

The join token is marked `sensitive`, so read it with `-raw`:

```bash
terraform output -raw cluster_token
```

> **The join token and the generated worker private key both live in the
> Terraform state**, as does `tailscale_auth_key` when you set it. Use an
> encrypted remote backend and restrict who can read it.

Example consumption from a root module:

```hcl
output "master_ips" {
  value = module.hcloud_kubernetes_cluster.master_nodes_ips
}

output "api_endpoint" {
  value = module.hcloud_kubernetes_cluster.control_plane_endpoint
}
```

## 5.3 Resources created

| Resource | Terraform address | Count |
| --- | --- | --- |
| Private network | `hcloud_network.private_network` | 1 |
| Master / worker firewalls | `hcloud_firewall.master_kubernetes_firewall`, `hcloud_firewall.worker_kubernetes_firewall` | 1 each |
| Subnet | `hcloud_network_subnet.private_network_subnet` | 1 |
| Master server(s) | `hcloud_server.master_nodes` | `master_nodes_number` |
| Worker server(s) | `hcloud_server.worker_nodes` | `worker_nodes_number` |
| Uploaded admin SSH key | `hcloud_ssh_key.admin` | 1, or 0 when `ssh_public_key` is unset |
| Worker node key pair | `tls_private_key.worker_node` | 1 |
| Cluster join token | `random_password.k3s_token` | 1 |
| Placement groups | `hcloud_placement_group.kubernetes_placement_group` | `ceil(nodes / 10)`, or 0 when `use_placement_group` is `false` |
| API load balancer | `hcloud_load_balancer.control_plane` | 1 when the control plane is HA, else 0 |
