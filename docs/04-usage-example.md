# 4. Usage example

A complete, runnable example lives in [`examples/basic`](../examples/basic). This
page reproduces and explains it.

## 4.1 The example

```hcl
# examples/basic/main.tf
module "hcloud_kubernetes_cluster" {
  source = "../../"

  # Cluster size
  worker_nodes_number = 2
  master_nodes_number = 1

  # Node hardware / image
  node_image       = "ubuntu-24.04"
  master_node_type = "cax11"       # ARM64, shared vCPU
  worker_node_type = "cax11"
  node_location    = "fsn1"        # Falkenstein

  # When both public address families are off, use Tailscale to keep a path to
  # the nodes and the API (see 4.3).
  use_public_ipv4 = true
  use_public_ipv6 = true

  # Spreads the nodes over separate physical machines, so one host failure does
  # not take several nodes with it.
  use_placement_group = true

  # The only key you provide: the public key of your own machine.
  # The key pair used between master and worker nodes is generated by the module.
  # Optional - leave it unset and pass `ssh_keys` instead if the key already
  # exists in your Hetzner project.
  ssh_public_key = var.ssh_public_key

  # Networking
  private_network_ip_range        = "10.0.0.0/16"
  private_network_zone            = "eu-central"
  private_network_type            = "cloud"
  private_network_subnet_ip_range = "10.0.1.0/24"
}
```

```hcl
# examples/basic/variables.tf
variable "hcloud_token" {
  type        = string
  description = "Hetzner Cloud API token"
  sensitive   = true
}

variable "ssh_public_key" {
  type        = string
  description = "Public SSH key of your own machine, e.g. file(\"~/.ssh/id_ed25519.pub\"). Optional if you set ssh_keys instead."
  default     = null
}
```

```hcl

  description = "Master Nodes IP Addresses"

}

```

## 4.2 A more realistic root module

Rather than hardcoding secrets, load real key material from files and the token
from the environment:

```hcl
module "hcloud_kubernetes_cluster" {
  source = "github.com/pawel150199/hcloud-k8s-cluster"

  master_nodes_number = 1
  worker_nodes_number = 3

  master_node_type = "cx33"      # bump size for real workloads
  worker_node_type = "cx33"
  node_location    = "nbg1"      # Nuremberg

  # Either upload your own public key...
  ssh_public_key = trimspace(file("~/.ssh/id_ed25519.pub"))

  # ...or reference keys already present in the project. Using only `ssh_keys`
  # is a perfectly valid configuration - but do not omit both unless you turn
  # on Tailscale, because sshd accepts the `cluster` user only.
  ssh_keys = ["ops-laptop"]
}

output "master_ips" {
  value = module.hcloud_kubernetes_cluster.master_nodes_ips
}

output "control_plane_endpoint" {
  value = module.hcloud_kubernetes_cluster.control_plane_endpoint
}
```

## 4.3 Reaching the nodes over Tailscale

`use_tailscale` joins every node to your tailnet during cloud-init and turns on
Tailscale SSH, which is authorised by tailnet ACLs rather than by
`authorized_keys`. It is the one configuration in which the cluster is usable
with no SSH key input at all, and it is also how you reach nodes that have no
public IPv4.

```hcl
module "hcloud_kubernetes_cluster" {
  source = "github.com/pawel150199/hcloud-k8s-cluster"

  master_nodes_number = 3
  worker_nodes_number = 3

  use_tailscale      = true
  tailscale_auth_key = var.tailscale_auth_key   # ephemeral, pre-approved, short expiry

  # kubectl will dial the master over the tailnet, so the API certificate has
  # to name that address as well.
  extra_tls_sans = ["master-node-0.tail1234.ts.net"]

  # Nodes still need public IPv4 for outbound package and k3s downloads unless
  # you provide egress another way.
  use_public_ipv4 = true

  # With the tailnet in place, narrow public SSH to nothing you do not need.
  ssh_source_ips = ["203.0.113.4/32"]
}

variable "tailscale_auth_key" {
  type      = string
  sensitive = true
}
```

```bash
export TF_VAR_tailscale_auth_key="tskey-auth-…"
terraform apply

ssh cluster@master-node-0          # MagicDNS name, Tailscale SSH
```

The auth key is rendered into the nodes' cloud-init and stored in the Terraform
state — rotate it once the apply is done. The firewall opens `41641/UDP` for
Tailscale's direct peer connections on every node, regardless of this flag;
without it Tailscale still connects, but through DERP relays. See
[Architecture §2.8](02-architecture.md#28-tailscale).

## 4.4 Run it

```bash
cd examples/basic

export HCLOUD_TOKEN="…"
export TF_VAR_hcloud_token="$HCLOUD_TOKEN"
export TF_VAR_ssh_public_key="$(cat ~/.ssh/id_ed25519.pub)"

terraform init
terraform apply

# after cloud-init finishes on the master:
terraform output master_nodes_ips

# log in as the cluster user with your own key - root logins are refused
ssh cluster@"$(terraform output -json master_nodes_ips | jq -r '.[0]')"
```

## 4.5 Choosing values

| Setting | Common choices | Notes |
| --- | --- | --- |
| `master_node_type` / `worker_node_type` | `cx23`, `cpx31`, `cax11`, `ccx13` | Default `cx23`. `cax*` are ARM64; `cx*`/`cpx*`/`ccx*` are x86, `ccx*` dedicated vCPU |
| `node_location` | `fsn1`, `nbg1`, `hel1`, `ash`, `hil` | Keep nodes in one location for low-latency private networking |
| `node_image` | `ubuntu-26.04` (default), `ubuntu-24.04`, `debian-13` | cloud-init assumes an `apt`-based image |
| `worker_nodes_number` | `1`–`N` | Scale by changing this and re-applying |
| `master_nodes_number` | `1`, `3`, `5`, `7` | `1` is a single control plane on SQLite. Above 1 the masters form an HA control plane on embedded etcd, which needs a quorum, so the value must be odd |
| `ssh_key_algorithm` | `ED25519`, `RSA`, `ECDSA` | Algorithm of the key pair the module generates for node-to-node access |
| `use_tailscale` | `false`, `true` | `true` needs `tailscale_auth_key`; gives Tailscale SSH and an access path independent of the public addresses |
| `use_placement_group` | `true`, `false` | Spreads nodes over separate physical hosts; sharded over `ceil(nodes / 10)` groups |
| `ssh_source_ips` / `kube_api_source_ips` | `["0.0.0.0/0", "::/0"]` | Firewall sources for SSH and the API. Narrow both where you can |
| `extra_tls_sans` | `[]`, `["k8s.example.com"]` | Extra names on the API server certificate. Required for any address you point `kubectl` at that is not a master IP or the load balancer |

### Scaling notes

Going from a single master to an HA control plane changes the first master's
cloud-init, which replaces the server and therefore rebuilds the cluster. Decide
on the control plane size before the first apply if you can.

Large clusters run into limits that are not Terraform's:

| Limit | Value | How the module handles it |
| --- | --- | --- |
| Servers per placement group | 10 | Spread over `ceil(nodes / 10)` groups automatically |
| Servers per network | 100 | A `check` block warns; raising it needs a Hetzner support request |
| Servers per project | quota, often low by default | Raise it with Hetzner support before applying |
| API requests | 3600/hour per project | Not handled by the module — pass `-parallelism=5` on apply and destroy, see [Applying a large cluster](06-operations.md#applying-a-large-cluster) |

The default `master_node_type` of `cx23` is sized for a small cluster. A control
plane serving many workers, or running embedded etcd for an HA setup, wants
dedicated vCPUs (`ccx*`): etcd commits every write to disk before acknowledging
it, so the CPU and I/O jitter of a shared-vCPU instance turns into missed raft
heartbeats and leader elections long before the machine looks busy. The default
is deliberately left alone — raise it yourself when the cluster grows.
